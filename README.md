# 빈또당

빈손으로 또 당첨. 지금 응모 가능한 **인스타그램 경품 이벤트**를 매일 아침 자동으로 모아 한 페이지로 보여줍니다.

👉 **https://spacehwi.github.io/binttodang/**

## 하는 일

- [이벤트하우스](https://www.eventhouse.kr/site/instagram.php?view=1)의 인스타그램 진행이벤트 목록을 긁어옵니다 (하루 1회, 약 700~900건).
- 각 이벤트의 **실제 인스타그램 게시물 주소**를 확인해서, 목록에서 바로 게시물로 넘어갈 수 있게 합니다.
- 경품·마감일·응모방법을 정리하고 마감일순으로 배치합니다.
- 키워드 규칙으로 `고가 경품` / `런닝·운동` / `간편(댓글만)` 을 자동 분류합니다.

## 구성

| 파일 | 설명 |
|---|---|
| `scrape.py` | 수집 + `index.html` 생성. 분류 규칙(`RE_BIG`, `RE_RUN_PRIZE`, `RE_RUN_HOST`, `RE_HARD`)이 파일 상단에 모여 있습니다. |
| `index.html` | 자동 생성되는 결과 페이지. 직접 고치지 마세요, 다음 갱신 때 덮어씁니다. |
| `data.json` | 수집 원본. 확인된 인스타그램 주소 캐시 역할도 해서, 다음 실행 때 새로 등록된 건만 조회합니다. |
| `.github/workflows/update.yml` | 매일 06:30 KST 자동 실행. Actions 탭에서 수동 실행도 가능합니다. |

## 직접 돌려보기

```bash
pip install requests beautifulsoup4 lxml
python scrape.py
open index.html
```

## 분류가 틀렸을 때

전부 키워드 규칙이라 가끔 엉뚱하게 잡습니다. `scrape.py` 상단의 정규식만 고치고 커밋하면 다음 갱신부터 반영됩니다.

예를 들어 `RE_RUN_HOST`에서 `짐`을 쓰면 '다짐'이 걸리고, `크루`를 쓰면 '봄내크루' 같은 지역 캐릭터가 걸립니다. 좁게 쓰는 편이 낫습니다.

## 수집이 막히거나 실패하면

이벤트하우스가 구조를 바꾸거나 접근을 차단하면 수집이 실패할 수 있습니다. 그때 어떻게 되는지:

- `scrape.py`는 수집 결과가 20건 미만이면 **파일을 덮어쓰지 않고 실패**합니다. 잘못된 빈 페이지로 갈아엎는 대신 마지막 정상 목록이 그대로 남습니다.
- Actions 실행이 실패하면 깃허브가 저장소 소유자에게 메일로 알립니다.
- 페이지 자체도 빌드 날짜를 알고 있어서, **2일 이상 갱신이 안 되면 상단에 경고 배너**가 뜹니다.

차단 위험을 낮추려고 하는 것들:

- 하루 1회만 실행 (목록 21페이지 + 신규 등록분 인스타 주소 조회 약 40건).
- 이미 확인한 인스타 주소는 `data.json`에 캐시해서 다시 조회하지 않습니다.
- 요청 사이에 딜레이를 둡니다 (목록 0.6초, 주소 조회 0.35초).
- 일반 브라우저 User-Agent를 사용합니다.

그래도 막히면 선택지는 두 가지입니다. 딜레이를 더 늘려 부하를 줄이거나, 다른 수집원(다나와 이벤트, 슈퍼투데이 등)을 `scrape.py`에 추가해 이중화하는 것입니다.

## 참고

- 경품 정보의 원 출처는 이벤트하우스입니다. 개인 용도로 하루 1회만 수집합니다.
- 응모 조건(팔로우 유지 등)과 발표일은 각 인스타그램 게시물 본문을 확인하세요.
- 체크박스 상태는 브라우저에만 저장되며 서버로 전송되지 않습니다.
